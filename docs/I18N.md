# Translations (English, Russian)

The interface is in English and Russian (header → language menu). Uzbek is listed as "Soon".

## How it works

- Engine: **react-i18next** (`i18next` + `react-i18next`), set up in `src/shared/i18n/index.ts`. Use our wrappers, not i18next directly: `useT()` in components, `translate()` outside React (hooks' toasts, error helpers), `plural()` for counts, `useLocalized()` to show a record's own `*_ru` text in Russian, month/weekday names. The header's language menu (UI store) drives `i18n.changeLanguage`.
- **The English text is the key.** `t('Create project')`. The Russian dictionary maps English → Russian; a missing entry shows the English text (never a key).
- Placeholders: `t('Delete {name}?', { name })`. The same `{name}` must appear in the Russian value.
- Russian dictionary: `src/shared/i18n/ru/*.ts`, one file per area, each `export default { 'English': 'Русский', … }`, merged automatically. Put a string in the file of the area that uses it; a string used in several areas belongs in `core.ts`.

## What is translated, and what is not

| Translated by us (dictionary) | Not translated by us |
| --- | --- |
| Page titles and descriptions, buttons, menu items, filters, tabs, table headers we name ourselves, empty/error/loading texts, toasts, dialogs, tooltips, `aria-label`s, form hints and our validation messages | **Field names and select options**: they come from u-code's schema in each language (`useTableFields` → `fieldLabel` / `optionLabel` / `fieldOptions` return `label_ru` in Russian). Never put a u-code field label in the dictionary. |
| Units we write ourselves ("days") | **Data**: names, amounts, record values, content. |
| | **Backend messages** (`backendMessage`): shown as u-code sent them. |
| | Ticker-like codes and currency codes (USD, UZS), "FAQ", "PINFL" style acronyms used as-is in Russian too (ПИНФЛ is fine for PINFL). |
| | The Excel export (it already follows the accepted Russian report). |

Fields without a Russian name in u-code fall back to English; the list for the backend team is in `docs/API.md` → "Missing Russian labels".

## Russian style

- Formal "вы", short, plain. Buttons are verbs in the infinitive: «Создать проект», «Сохранить», «Отмена», «Удалить».
- **No nouns glued into sentences.** Shared components get English nouns from pages ("No {noun} yet"); Russian cases make that ungrammatical, so their Russian text is noun-free: «Пока ничего нет», «Не удалось загрузить данные», «Запись удалена», «Удалить запись?». Where a page has the full sentence, translate the full sentence.
- Sentence case, no trailing period on labels and buttons; full stops in descriptions and messages.
- Dates stay `12.11.2026`; numbers keep the app's format (space for thousands, dot for decimals, `UZS` after, `$` before).
